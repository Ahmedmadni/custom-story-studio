# قائمة اختبار QA — حكايتي

تشيك ليست يدوية كاملة للتأكد من سلامة المسارات قبل الإطلاق أو بعد أي تغيير كبير.
علّم ✅ / ❌ أمام كل بند.

## 1) المصادقة والصلاحيات
- [ ] تسجيل دخول بالبريد + كلمة المرور يعمل.
- [ ] تسجيل دخول Google يعمل (لو مُفعّل).
- [ ] أول مستخدم يُسجَّل يحصل تلقائياً على دور `admin` (handle_new_user).
- [ ] صفحة `/admin` تُحجب عن المستخدم العادي مع رسالة واضحة.
- [ ] الـ routes تحت `_authenticated` تحوّل غير المسجّل إلى `/auth`.
- [ ] تسجيل الخروج يمسح الجلسة ويعيد التوجيه.

## 2) المكتبات
- [ ] `/stories` يعرض شِيمر ثم القصص بدون أخطاء RLS.
- [ ] فلاتر التصنيف تعمل وتُعيد بطاقات صحيحة.
- [ ] حالة فارغة `EmptyState` تظهر عند فلتر بلا نتائج.
- [ ] حالة خطأ `ErrorBlock` تظهر وتعمل إعادة المحاولة عند قطع الشبكة.
- [ ] `/books` يعرض الكتب التعليمية فقط (`content_type=book`).
- [ ] الضغط على بطاقة قصة يفتح `/stories/{slug}` بدون شاشة بيضاء.

## 3) مسار الطلب (Order Flow)
- [ ] من `/stories/{slug}` زر «اطلبها بصورة طفلك» يفتح `/order/{templateId}`.
- [ ] رفع صورة الطفل ينجح إلى bucket `child-photos`.
- [ ] حقول: اسم الطفل، العمر، رقم واتساب (E.164) تتحقّق صحّتها.
- [ ] إنشاء الطلب يُدرج صفّاً في `orders` بحالة `pending`.
- [ ] الطلب يظهر فوراً في `/admin` للأدمن.

## 4) لوحة الأدمن
- [ ] قائمة الطلبات تُحمَّل (لا 401 / لا permission denied).
- [ ] تفاصيل الطلب تعرض صورة الطفل والبيانات.
- [ ] زر «موافقة» يحوّل الحالة إلى `approved`.
- [ ] زر «توليد كل الصفحات المتبقية» يولّد الصور بنمط cinematic 3D.
- [ ] عدد الصور المولّدة يتطابق مع طول القصة (لا صور ناقصة).
- [ ] الصور تحافظ على ملامح الطفل عند رفع صورة حقيقية.
- [ ] العناصر التعليمية في صفحات الكتب متنوّعة (تفاحة+عنب+موز، ليست تفاحة مكرّرة).
- [ ] الحالة تصبح `ready` بعد اكتمال كل الصفحات.
- [ ] زر «إرسال عبر الواتساب» يفتح `wa.me/{رقم}` برسالة جاهزة + رابط القصة.
- [ ] الحالة تتحوّل إلى `sent` بعد فتح الواتساب.

## 5) معالج الإنشاء `/create`
- [ ] الخطوات الـ 8 تتنقّل بدون فقدان البيانات.
- [ ] خطوة الصورة: cartoonize vs real-face-on-3D-scene يعمل كلاهما.
- [ ] خيار اللغة (ar / en / bilingual) ينعكس على النص المولّد.
- [ ] زر «توليد» يبدأ الإنشاء (سُجِّل سابقاً عُطل — تأكد أنه يعمل الآن).
- [ ] خطوة المعاينة تسمح بتعديل النص وإعادة توليد صورة الصفحة.
- [ ] زر «اعتماد» يثبّت `approved_at` في DB.
- [ ] لا يمكن تصدير PDF قبل اعتماد المستخدم وقبل اعتماد الأدمن (`admin_approved_at`).
- [ ] PDF نهائي مربّع، بلا هوامش بيضاء، النص فوق الصورة، خطوط Cairo/Tajawal.

## 6) اعتماد الأدمن للقوالب المخصّصة
- [ ] قسم «محتوى ينتظر اعتمادك» يظهر للقوالب المعتمدة من المستخدم وغير المعتمدة إدارياً.
- [ ] «اعتماد ونشر» يضع `admin_approved_at` ويسمح بتحميل PDF.
- [ ] «إعادة للتعديل» تُلغي `approved_at` للمستخدم.

## 7) الموبايل + RTL
- [ ] كل الصفحات RTL سليم (الـ flex لا ينعكس بصرياً).
- [ ] أزرار ≥ 44px (لمسة مريحة).
- [ ] شريط الفلاتر `FilterChips` يقبل التمرير الأفقي على الموبايل.
- [ ] الستيبر في `/create` يظهر بشكل متجاوب.

## 8) أداء وأمان
- [ ] لا أخطاء في الكونسول على أي صفحة.
- [ ] لا 403/permission على الاستعلامات (تأكد من GRANTs).
- [ ] الأسرار (SUPABASE_SERVICE_ROLE_KEY, LOVABLE_API_KEY) غير مكشوفة في bundle العميل.
- [ ] صور `child-photos` غير قابلة للوصول من غير صاحبها (RLS على bucket).

## 9) قائمة جاهزية الإطلاق (Launch Checklist — M5)

### أجهزة ومتصفحات
- [ ] موبايل (iOS Safari + Android Chrome) — تخطيط سليم، لا نص مقصوص، الأزرار قابلة للمس.
- [ ] تابلت (iPad أو ما يعادله) — الشبكات (grid) تتكيّف بدون فراغات غريبة.
- [ ] ديسكتوب (≥1280px) — المحتوى لا يتمدّد بلا حدود على شاشات عريضة جداً.
- [ ] Safari (macOS/iOS) — تحقّق خاص من `backdrop-blur`، `dir="rtl"`، وحقول الرفع.
- [ ] Chrome — المتصفح المرجعي، يجب أن يعمل كل شيء بلا استثناء.
- [ ] Edge — عادة يتبع Chromium، لكن تحقّق من أي إضافات متصفح تتعارض مع الرفع/الدفع.
- [ ] Firefox — تحقّق من `line-clamp`، الخطوط العربية (Cairo/Tajawal)، والـ sticky header.

### إتاحة (Accessibility)
- [ ] كل صورة معلوماتية لها `alt` وصفي؛ الصور الزخرفية `alt=""`.
- [ ] تباين الألوان كافٍ للنص فوق الخلفيات المتدرّجة (خصوصاً badges الملوّنة).
- [ ] كل عنصر تفاعلي (زر/رابط) يمكن الوصول إليه بالـ Tab وله `focus` مرئي.
- [ ] النماذج (تسجيل، دفع، إنشاء طفل) لها `label` مرتبط بكل حقل.
- [ ] الحوارات (Dialog/Modal — بما فيها معالج الإعداد الأول) تُغلَق بـ Escape ولا تحبس التركيز.

### SEO
- [ ] `/sitemap.xml` يُرجع XML صالحاً ويتضمّن كل قصة منشورة.
- [ ] `/robots.txt` يسمح بفهرسة الصفحات العامة ويمنع `/admin` وصفحات الحساب.
- [ ] كل صفحة عامة رئيسية لها `title` و`description` فريدين، ورابط `canonical` صحيح.
- [ ] JSON-LD يمرّ بدون أخطاء عبر [Rich Results Test](https://search.google.com/test/rich-results).

### أداء
- [ ] لا صور بلا `loading="lazy"` في القوائم الطويلة (مكتبة القصص، طلباتي، المفضلة).
- [ ] لا Layout Shift ملحوظ عند تحميل الصور (استخدم أبعاداً ثابتة أو `aspect-ratio`).
- [ ] وقت التحميل الأول (LCP) على شبكة 4G مقبول لصفحة الرئيسية وصفحة القصة.
- [ ] لا استعلامات Supabase مكرّرة غير ضرورية (تحقّق من React Query DevTools).

### أمان
- [ ] **معروف**: جدول `profiles` بلا سياسات RLS (GRANT فقط) — راجع قبل الإطلاق العام،
      فهذا يسمح نظرياً لأي مستخدم موثّق بقراءة/تعديل صفوف مستخدمين آخرين.
- [ ] لا مفاتيح API أو أسرار مكشوفة في مصدر الصفحة (`view-source:`) أو في bundle العميل.
- [ ] `SUPABASE_SERVICE_ROLE_KEY` يُستخدم فقط داخل ملفات `*.server.ts` أو مُعرَّفات الخادم.
- [ ] نقاط النهاية الإدارية (`/admin/*`) تُحجب فعلياً عن غير الأدمن (تحقّق يدوياً بحساب عادي).
- [ ] كوبونات الخصم لا يمكن إساءة استخدامها (حد الاستخدام لكل مستخدم يُطبَّق فعلياً).
